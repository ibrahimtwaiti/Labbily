## Safe local setup
Use Python 3.12+, venv, pip install -r requirements.txt, npm ci for dev tools, read .env.example and scripts/browser_server.py, then set isolated local/temporary DB explicitly. `python -m labbily.cli init` and bootstrap only after confirming local target, interactive credentials. `npm run dev` or `python -m uvicorn labbily.main:app --host 127.0.0.1 --port 8000`. Worker only with isolated environment/no live keys. See README and CI for exact commands and PostgreSQL configuration.
## Tests
`python -m unittest discover -s tests -v`; `python -m compileall -q labbily scripts`; `npm run check`; Playwright via CI (Chromium, Firefox, WebKit), PostgreSQL with disposable DB. Verify migration from prior schema, tenant isolation, browser RTL/LTR, failure cases, synthetic load, no real provider requests. Existing scripts smoke_production/backup/restore/retention must not run against production without authorization; use isolated equivalent.
## Release gate
Branch -> PR -> review diff and CI for exact SHA -> isolated staging with separate DB/secrets -> functional/security/performance evidence -> owner approval -> approved merge and deployment -> smoke/health + rollback readiness. Production release and commercial/provider activation are distinct approvals. Monitor queue, failed jobs, webhook dedup, backup freshness, cost; test restore in isolation. Rollback requires compatible schema, no replay of unknown delivery, preserve database and audit history.
