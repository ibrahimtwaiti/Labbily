# External integrations
## Meta
WhatsApp Business Platform Embedded Signup / Cloud API; WABA and phone IDs, onboarding, lifecycle, templates, media, statuses, signature validation, retry and dedup. Messenger, Instagram, Pages, catalogs, Lead Ads and Marketing Insights documented with separate eligibility/scopes/permissions; ad insights read-only. Real permissions, app review, Tech Provider status, verification and business/account eligibility must be established from authorized Meta account. A local OAuth or signed fixture is not proof of actual grant. Never call unofficial message APIs or store user access tokens in browser/Git. Revoke/disconnect and test reauthorization; do not retry uncertain external sends blindly.
## OpenAI
Prefer cost-effective models for standard customer responses with human escalation. Select via provider control, verified model IDs/prices, tenant-specific policy/budget, token ceilings, caching where supported, appropriate reasoning level, published knowledge retrieval, structured tools/validation. Test Arabic customer-service quality and safety on synthetic/consented samples; track per-company tokens/cost and Meta charges separately. Proposed benchmark 500–1000 scenarios, not executed or a binding model choice. No paid test or live customer content without authorization. Current implementation model/provider support must be read in agent_engine/runtime_configuration, not inferred from desired feature list.
## Storage / email / workers
R2 private media and backups documented; validate upload scanner, signed private reads, retention, restricted credentials and restore separately. SMTP test previously reported; durable sender configuration and notifications need current verification. Worker/Neon scheduled drain documented; verify queue age and retries. External appointment/order actions must use approved endpoint, data minimization, signed calls, action approval, idempotency and timeout handling.
