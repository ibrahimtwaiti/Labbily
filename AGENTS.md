## Invariants
- Preserve auth, RBAC, tenant boundaries, API contracts, public routes, existing capabilities and Labbily brand. Scope every read/write/job/cache/file/AI retrieval by authenticated tenant and role; validate object ownership server-side. Test cross-tenant access, concurrency and retries. Never trust tenant IDs supplied by UI alone.
- Provider operations, accounts, integrations, model policies and feature toggles belong in the authorized provider console, not hardcoded credentials or manual source edits.
- No secrets, customer data, access tokens, private URLs with credentials, or raw private conversations in this public Git repository. Use .env.example variable names only; separate production and staging credentials. Do not echo env or logs containing PII. No production DB writes, schema changes, live external sends, real billing, provider setup, merge or deployment without specific authorization. Treat exposed secrets as compromised; propose rotation, do not reproduce them.
- Keep Arabic RTL and English LTR, keyboard/focus, contrast, mobile and reduced-motion. Reuse shared loading/empty state and design tokens. Inspiration is not permission to copy competitors' assets/code.
- AI: OpenAI is the preferred provider for economical customer replies; model IDs and costs require current verification and owner approval. Ground answers in authorized published knowledge; human handoff on uncertainty or risky action. No cross-tenant retrieval; enforce quotas, action approvals, tool allowlists and data minimization.
## Development
Python 3.12+, FastAPI, static JS/CSS/HTML SPA; PostgreSQL on Neon, SQLite local. Use isolated disposable data. Read README and CI before running. Typical commands: pip install -r requirements.txt; python -m unittest discover -s tests -v; python -m compileall -q labbily scripts; npm ci; npm run check; npx playwright test (configure isolated test DB and browser dependencies first; follow CI). Do not run init/bootstrap/migrations against production. Verify environment/target before any command.
Work in task branches, small reviewable commits, no force push. Include tests for changed behavior and explicit failure paths. Record exact SHA, test command/result, environment and limitations; distinguish implemented, tested, live verified and approved. Update relevant knowledge docs. A green CI or READY deployment does not imply Meta approval or commercial launch. On handover, report unresolved Work-only artifacts; never assert recovered unpushed work.
